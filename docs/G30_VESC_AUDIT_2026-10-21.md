# G30 VESC compatibility source audit (2026-10-21)

Scope: code inspection only. **No motor test, hardware validation, build, IAP flashing, bootloader or recovery change performed.** Confirmed FO7x IAP experience is the reference; it must not be equated with qualification of a different application image.

## Verified code facts
- `common_files/src/VescCommand.c`: G30-specific dispatcher handles FW_VERSION, GET_VALUES (+SELECTIVE), SET_CURRENT, SET_CURRENT_BRAKE, SET_MCCONF, GET_MCCONF, DETECT_APPLY_ALL_FOC, APP_DISABLE_OUTPUT and ALIVE.
- G30 `COMM_DETECT_APPLY_ALL_FOC` invokes an RTOS worker; measures R/L and flux; derives current PI and observer gain, stores configuration; no hardware proof for this exact integration.
- App configuration commands (`COMM_GET_APPCONF`, `COMM_SET_APPCONF`) and several other upstream VESC commands are absent from the G30 compact switch; *full* VESC Tool compatibility must not be claimed.
- `common_files/src/g30_sensorless.c`: normal PWM start requires valid motor parameters and rolling/BEMF lock, with separate open-loop detection mode. Thus no normal torque from complete standstill via this code path; kick-start is expected.
- `common_files/src/app_uartcomm.c`: native ADC controller provides brake priority when `ADC_CTRL_TYPE_CURRENT_NOREV_BRAKE_ADC` is selected.
- `common_files/src/g30_recovery_iap.c`: recovery exists inside application, not independent of its boot sequence. No changes made.
- `common_files/src/VescToSTM.c`: corrected existing temp-derating typo using battery cutoff endpoint instead of temperature cutoff endpoint. Must verify via build and controlled thermal simulation.

## Agreed motor-start requirements (2026-10-21)
- **Normal riding:** push the scooter to approximately **3 km/h**, then apply throttle. The firmware shall use passive BEMF/rolling detection to acquire rotor position; no self-start from a complete stop is required for normal riding.
- **VESC Tool FOC Detect All only:** permit controlled active open-loop spin from a standstill as required to measure R/L/flux. Detection must remain distinct from normal throttle-based drive.
- **Code observation:** `G30SL_PreparePwmStart()` already bypasses rolling lock during `open_loop` and otherwise requires rolling lock plus valid motor parameters. `G30SL_Configure()` derives `min_speed_unit` from 3 km/h, pole count, and wheel diameter, but clamps to [60,1000]; verify actual wheel speed/pole semantics and BEMF lock on hardware before claiming an exact 3 km/h trigger.
- **Acceptance tests:** (1) no normal drive torque at rest; (2) kick/push above ~3 km/h, then throttle engages smoothly; (3) FOC Detect All can rotate a stationary *free* wheel on current-limited bench supply, with abort and result validation; (4) no automatic movement outside explicitly requested detection.
- No change to existing motor-start code in this documentation-only update; preserve the proven behavior until test results justify a change.

## Point 3.1: FOC Detect All start ordering and return to riding mode (2026-10-21)

**Confirmed source bug:** On G30, `G30SL_PreparePwmStart()` accepts stationary PWM only after `SPD->open_loop` is enabled. In `common_files/src/tune.c` the resistance, inductance and flux measurement paths previously called `VescToSTM_pwm_force(true, true)` **before** enabling open-loop. Consequently, the initial PWM request could be rejected by the normal rolling-start gate.

**Fix in G30-specific paths:** Enable open-loop before requesting PWM in resistance, inductance and flux measurement. Other board variants retain their existing order under `#ifndef G30P`. After flux measurement, including abort/failure, command zero current, switch PWM off, then exit open-loop, retaining the normal ~3 km/h rolling-start behavior.

**Kept unchanged:** Open-loop flux compensation factor `lambda *= 2` (requires FO7x cross-check); VESC Tool's `COMM_DETECT_APPLY_ALL_FOC` response and configuration storage behavior; preset detection currents; `G30SL_PreparePwmStart` and its 3 km/h threshold; dashboard and all IAP/boot/recovery code. No new gate, timeout or lockout.

**Build and source-level regression:** [STM32 Build 39641175157](https://github.com/ZachWay9bot/SmartESC_STM32_v21b/actions/runs/39641175157) passed `Build G30P`, with text 50,708 bytes, data 1,364 bytes, BSS 18,728 bytes. Flash load **52,072 of 55,296** bytes (free **3,224**). [Host regression 39641175124](https://github.com/ZachWay9bot/SmartESC_STM32_v21b/actions/runs/39641175124) passed **9 tests**, including four new detection order/cleanup/source checks. Recovery audit passed.

**Remaining before hardware claim:** host source tests cannot prove PWM timing, R/L/flux accuracy, current sensing, motor startup, VESC Tool 6.06 full Detect All session, flash store/readback or abort at the bench. SHU packaging stays blocked by existing independent UART stock-restore prerequisite; no candidate flash BIN published or IAP flashed.

## Point 3.2: rolling-BEMF lock and FOC handoff (2026-10-21)

**Hardware findings / source verification**
- G30 ADC1 uses `ADC_DATAALIGN_LEFT` (`g30p/Src/main.c`), so the 12-bit regular-channel data really must be decoded as `ADC1->DR >> 4`. The three separate phase-voltage inputs are ADC channels 6 (PA6), 7 (PA7), 9 (PB1). **Do not change the ADC alignment or BEMF pin mapping without hardware evidence.**
- `G30SL_PassivePoll()` runs in the medium-frequency motor task with PWM off. `G30SL_PreparePwmStart()` continues to require nonzero valid R/L/flux and fresh rolling lock for normal throttle engagement. Open-loop detection remains an exception; no code was added to self-start riding.

**Confirmed logic fixes**
1. After low BEMF span, clear accumulated valid forward/reverse sector edges and filtered period as well as the former sector/lock. Otherwise one new edge can complete a stale lock from before an interruption.
2. On invalid sector jumps/timing, also discard stale direction and reported electrical speed.
3. Re-evaluate `rolling_locked` at each valid edge, so falling below the existing `min_speed_unit` threshold releases a previous lock. This fixes a latch bug rather than adding a new safety mode or threshold.
4. `conf_general_setup_f_sw()` already writes the actual sensor measurement frequency (accounting for regulation execution every 2nd PWM cycle above 20 kHz). `G30SL_Configure()` previously overwrote it with raw PWM frequency. Keep the preconfigured actual frequency for electrical angle DPP conversion and observer step divider. Default 16 kHz behavior is preserved.

**Pole semantics**
- VESC `si_motor_poles` is **total magnetic poles**, while the BEMF threshold and dashboard speed use `pole_pairs = si_motor_poles / 2`.
- Gen 1 serial prefix **6** and Gen 2 serial prefix **9** distinguish motor generations. They do **not** establish six or nine electromagnetic pole pairs. Source: ScooterHacking's Ninebot Max identification wiki, `https://github.com/scooterhacking/wiki/blob/main/pages/nbmax.txt`. Existing fallback to 30 poles (15 pairs) is deliberately unchanged until the installed motor's electrical cycles per mechanical wheel revolution can be measured. It must not be sold as hardware-confirmed.
- With the default 0.243 m wheel circumference and gear ratio 1, 3 km/h corresponds to approximately **65** speed units for 12 magnetic poles, **98** for 18 poles, and **164** for 30 poles. These are **simulated configuration examples**, not verified motor pole counts.

**Regression and build**
- Real portable `g30_sensorless_core.c` is compiled and tested on the host with synthesized A/B/C BEMF waveforms: acquire just above threshold after four correct edges; reject below-threshold acquisition; drop a prior lock as speed decreases; clear old edges after voltage dropout; reject invalid sector leaps and stale samples; preserve signed forward and reverse detection.
- Additional source checks confirm ADC alignment/channel wiring and frequency scaling. Full suite: [13 tests passed, run 39679573574](https://github.com/ZachWay9bot/SmartESC_STM32_v21b/actions/runs/39679573574); [G30 build run 39679573552](https://github.com/ZachWay9bot/SmartESC_STM32_v21b/actions/runs/39679573552) passed compile/link: text **50,724**, initialized data **1,364**, BSS **18,728**, flash load **52,088 / 55,296 bytes**, leaving **3,208 bytes**.
- Full CI run still fails only at unchanged package generation: **independent UART stock-restore unverified**; do not bypass or modify this release hold without discussion and express approval.
- **Not yet demonstrated on motor:** phase ordering, ADC waveform shape/voltage scaling, actual pole pairs, electrical-angle sign, observer lock/current regulation after PWM enable, correct real-wheel handoff at 3 km/h. Those require the controller and a free-wheeling motor under current-limited lab supply.
- No changes to bootloader, IAP/recovery, flash layout, motor parameters, physical FOC PWM frequency, dashboard UART or default pole setting.
